# Changelog

Per-release notes are generated by GoReleaser from the commit log and published
on the [releases page](https://github.com/lgldsilva/ai-launcher/releases) — this
file does not duplicate them.

What lives here is the part a commit log cannot carry: **breaking changes and
the migration each one needs**. If an upgrade is going to ask something of you,
it is written down below.

Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); the
project follows [semantic versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Changed — config schema 2.0 → 2.1

`trusted_local_configs` in `~/.config/ai-launch/config.yaml` changed from a list
of bare SHA-256 strings to a list of `{path, hash}` records. A hash proves the
bytes, not the file: without a path bound to it, a cloned repository shipping an
identical `.ai-launch.yaml` inherited the trust its author had recorded.

**What you need to do:** run `ai-launcher --save` once in each workspace where
you had previously saved a selection. Until you do, those workspaces are treated
as unsaved and the local-config trust boundary applies to them again.

**What you do not need to do:** anything else. A 2.0 file still loads, and your
catalog, profiles, MRU list and `memory_auth_token` are untouched. The old rows
are read, ignored for trust, and rewritten on the next save.

Downgrading is one-way: a 2.1 config is not loadable by a pre-2.1 binary, which
now fails with `unsupported config version "2.1"` instead of a YAML type error.

### Changed — the sandbox now states the Docker decision explicitly

Every jailed command carries `--docker` or `--no-docker`. Previously the
launcher emitted nothing when the Docker permission was off, which left the
capability in ai-jail's auto mode — and through ai-jail v1.15.x, auto mode
bind-mounted an existing `/var/run/docker.sock` read-write with no flag and no
warning. Write access to that socket is root on the host
([ai-jail issue #88](https://github.com/akitaonrails/ai-jail/issues/88), fixed
upstream in v1.16.0).

**What you need to do:** nothing, unless you were relying on the socket being
auto-mounted without asking for it. If you were, enable the Docker permission
or pass `--docker`, and read the warning it comes with.

**If you script against the argv** (`--dry-run` output, wrappers): expect one
extra token immediately after `ai-jail` / `ai-jail --exec`.

`jail_flags.docker` is new and tri-state like its siblings, except that unset
is not auto — it means off.

### Changed — minimum ai-jail is now 1.16.0

`ai-launcher --doctor` reports `ai-jail-version-too-old` below 1.16.0. This is a
security floor, not a feature floor: the argv fix above protects 1.15.x hosts
too, but 1.15.x had no way to refuse the socket at all.

### Added — the local-config trust boundary covers `param_values`

A workspace `.ai-launch.yaml` that sets `options.param_values` is refused unless
you pass `--param`, matching how `yolo`, `extra_args` and `jail_flags` are
already handled. Catalog params choose the model the harness runs as, and a
`takes_value: false` param is a bare flag the file switches on by name.

**What you need to do:** if a repository you trust ships `param_values`, pass
`--param name=value` once, or `--save` the selection.

### Added — `jail_flags.save_config` controls ai-jail's automatic config writes

`jail_flags.save_config` is a new tri-state toggle mapping ai-jail v1.16's
`--save-config` / `--no-save-config`: it turns ai-jail's automatic `.ai-jail`
writes on or off. Unset leaves the ai-jail default in charge, `true` forces
`--save-config`, `false` forces `--no-save-config`. It is emitted right after
`hide_config`, its sibling for the same file.

**What you need to do:** nothing. This is additive; existing configurations are
unaffected and keep ai-jail's default behavior.
