## What to check hardest, in order

1. **`TrustedLocalEntry.UnmarshalYAML`** (`internal/config/config.go`). Whether
   goccy/go-yaml *errors* when decoding a bare scalar into a struct decides
   whether the legacy branch is ever reached. If goccy is permissive instead,
   the hash is silently dropped.
   `TestLegacyGlobalConfigStillLoadsWithAllKeysIntact` asserts the hash
   survives, so it fails loudly rather than quietly.

2. **The mechanical argv rewrites.** `--no-docker` was inserted into 17 Gherkin
   blocks, 22 Go `[]string{"ai-jail"…}` literals, 6 string-concatenated
   expectations in `launch_test.go`, and 8 README samples. Scripted and
   diff-reviewed, never executed. `make test-gherkin` is the fast check.

3. **`gofmt -l .`** Struct alignment and import order were verified with a
   hand-written checker, not gofmt. Structural soundness (brace depth, top-level
   declarations) was verified programmatically across all 19 changed Go files.

4. **`--workstream-search`** is new surface. The flag plumbing is covered by
   `cmd/ai-launcher/workstreamsearch_test.go` against a stub `ai-memory` on
   PATH, but the real subcommand's flag names (`--limit`, `--json`) come from
   upstream's blog post, not from `ai-memory workstream-search --help`. Confirm
   against the installed binary.

## Still open

**PR6 — the `ai-memory run` harness list.** `config.MemoryRunHarnesses()`
declares eight: `claude, codex, opencode, pi, crush, omp, kimi, grok`. Upstream's
support matrix documents MCP/hook clients, not managed-mode adapters, and the
author explicitly separates the two. His July write-up lists six managed
harnesses and describes Kimi Code and Grok Build CLI as MCP integrations.

Not changed, deliberately. Wrongly removing them makes pre-flight refuse a
harness that works; wrongly keeping them lets clap reject it inside the jail,
which is the failure this list exists to prevent. One command decides it:

```bash
for h in claude codex opencode pi crush omp kimi grok; do
  ai-memory run "$h" --help >/dev/null 2>&1 && echo "ok   $h" || echo "FAIL $h"
done
```

Then either trim the list and set `supports_memory: false` on the affected
catalog entries, or leave it and record in `config.go:42` which version verified
it.

**`ai-memory install-instructions`** was left out of the install flow. It writes
the routing block into `CLAUDE.md` / `AGENTS.md` in the current checkout, and
`--install` provisions binaries globally — folding a file-mutating step into it
would be a surprise. It wants its own flag and its own decision about which file
it may touch.

## Breaking changes to announce

Both are written up in `CHANGELOG.md` on `chore/hygiene-and-policy-docs`:

- **Config schema 2.1.** Saved local configs need one `--save` each to be
  trusted again. Nothing else is lost, and a 2.0 file still loads.
- **Argv shape.** Every jailed command gained `--docker` or `--no-docker`
  immediately after `ai-jail` / `ai-jail --exec`. Anything scripting the
  `--dry-run` output sees one extra token.
